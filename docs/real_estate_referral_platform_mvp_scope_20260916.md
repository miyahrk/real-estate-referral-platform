# 不動産紹介プラットフォーム MVP スコープ定義

**作成日：** 2026年9月16日
**方針：** 余計な機能は付けず、最小限で動くものを先に作り、後から機能追加していく

---

## 1. MVPの原則

- 宮崎さん本人に加え、少人数（数名程度）の試用ユーザーにも使ってもらえるようにする。複雑な権限設計はまだ不要だが、複数アカウントでのログインには対応する（※これは管理ワークスペース側の話）
- **エンドユーザー（見込み客）向けは、ログイン不要で完結させる**。情報閲覧→サービス申込までを、アカウント登録なしの最短導線で提供する（決済は現時点ではスコープ外）
- **決済（LINE Pay・PayPay等）は今回スキップ**。法人口座を持っていないため。ただし将来追加しやすいよう、決済プロバイダーを抽象化した設計方針だけは残しておく（特定の決済手段にロジックを結合させない）
- 自動マッチングなどの高度な機能は後回し。LINE連携は色々試したい意向のためMVPに含める
- まずは「案件を記録し、ステータスを追える」状態を作ることを最優先とする
- 企業HP共通基盤（マイクロサービス化・Headless CMS等）への統合は、MVPでは行わない

---

## 2. MVPに含める機能

| 機能 | 内容 |
|------|------|
| **HP（LP）** | 既に作成したプロトタイプをベースに、サービス紹介・お問い合わせ導線を掲載 |
| **問い合わせフォーム** | 見込み客が入力（氏名・連絡先・エリア・予算・投資目的） → DBに保存。アカウント登録は不要 |
| **ワークスペース（管理画面）** | 複数アカウントでログイン可能な画面＋案件一覧（宮崎さん＋試用ユーザー数名）※管理側のみログインが必要 |
| **案件ステータス管理** | 新規 → ヒアリング中 → 紹介済み → 成約／不成立 の手動更新 |
| **紹介先マスタ** | 紹介先の会社・担当者・対応エリア・専門分野を手入力で登録・一覧表示 |
| **LINE連携（実験枠）** | LINE Login・Messaging API・LIFF等を試験的に組み込む。用途は今後拡張しながら模索 |

---

## 3. MVPに含めない機能（後回しリスト）

| 機能 | 理由・追加時期の目安 |
|------|------------------|
| LINE Pay・PayPay等の決済 | 加盟店契約に法人口座が必要なため現時点ではスキップ。法人化・口座開設後に追加を想定 |
| Stripe等カード決済 | 同上。決済プロバイダー抽象化レイヤーは設計に含めておき、いつでも追加できるようにする |
| 紹介先向け専用ポータル（複数ユーザー） | 紹介先が増え、案件共有の負荷が上がったタイミングで検討 |
| 自動マッチングロジック | 案件データが一定量蓄積してから設計する方が精度が出る |
| Headless CMSによるコンテンツ管理 | 当面はHTML直書き・簡易更新で十分 |
| 複数企業HP共通基盤への統合 | 別プロジェクトの完成度を見てから判断 |

---

## 4. 技術スタック（プロジェクト共通アーキテクチャを踏襲、MVP用に絞り込み）

| レイヤー | MVPでの構成 |
|---------|------------|
| フロントエンド | Next.js（App Router）、React、TypeScript |
| バックエンド | Spring Boot（Java）— 最小限のAPI（問い合わせ登録・案件CRUD・ログイン）のみ |
| DB | PostgreSQL |
| 決済 | MVPでは未実装（スキップ）。ただし決済プロバイダーを抽象化するインターフェース（Adapter/Strategyパターン）の設計だけ用意しておき、法人口座取得後にLINE Pay・PayPay等を追加しやすくする |
| 認証 | 複数アカウント対応の簡易ログイン（メール＋パスワード、または将来的にLINE Login）※管理ワークスペース側のみ。エンドユーザー向けはログイン不要 |
| ホスティング | 未定（Vercel＋クラウドDBなど、コスト最小構成を想定） |

※ Headless CMS、マイクロサービス分割は本MVPには含めない。将来の拡張時に導入。

---

## 5. 最小限のデータモデル

```
leads（案件）
  id, name, contact, area, budget, purpose, status, created_at

referral_partners（紹介先マスタ）
  id, company_name, contact_person, area, specialty, notes, created_at

users（利用者：宮崎さん＋試用ユーザー。ワークスペースのログイン用）
  id, email, password_hash, role（admin / trial）, line_user_id（任意）

orders（サービス申込：エンドユーザーはアカウント不要）
  id, contact（氏名・連絡先のみ）, service_type, status, created_at
```

※ `payments`テーブルはMVPでは未実装。将来、決済プロバイダー抽象化レイヤーとあわせて追加する。

---

## 6. 次のアクション

1. 本MVPスコープを反映した着手指示書を、既存の企業HP共通基盤用指示書とは別ファイルで新規作成する
2. Claude Code（デスクトップ版・ネットワークアクセスあり）でリポジトリを初期化し、実装を開始
3. MVP完成後、実際の案件対応を通じて優先度の高い追加機能（決済・LINE連携の深化など）を見極める
